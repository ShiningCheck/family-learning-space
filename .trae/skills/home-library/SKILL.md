# 家庭图书馆

把家里的实体书架搬到网页上：**拍照即入库**（解析书名、出版社、内容简介），**按书架分层归档**，**有问题时按主题从自家书架上挑书**，并明确告诉孩子「在哪个书架、第几层」。

网页端是成长家园门户的「图书馆」标签页（`/lib/web/library.html`），带孩子拼音标注、语音朗读与「帮我找书」智能匹配。

## 目录结构（门户以 `/lib/*` 托管）

**代码侧**（本技能根目录，公开、可分发）：

```
home-library/
├── SKILL.md
├── skill.json            # 声明 url=lib / 代码目录 / 数据目录
├── DATA.md               # 数据落在哪里（仓库之外的 data-root）
├── web/
│   ├── library.html      # 图书馆页：书架分层陈列 + 找书推荐 + 图书详情/归架/添加
│   └── vendor/           # pinyin-pro.js + themes.js + tts.js + voice.js + feedback.js（与门户同款）
└── data-templates/       # 匿名初始数据（data-root 里的 data/ 由它生成）
```

**数据侧**（**仓库之外**，本技能目录里没有 `data/`、`images/`）：`<data-root>/lib/`
（`data/config.json` childName / libraryTitle、`data/shelves.json` 书架与层数配置、`data/books.json` 书目总表、
`images/covers/` 图书封面照片副本）。路径一律走 `tools/data_paths.py` 的 `skill_dir("home-library")` 解析，
细节见同目录 `DATA.md`。

用户发来的图书照片必须**复制**进 `<data-root>/lib/images/covers/`，不能只引用临时附件路径（附件会被清理）。

## 数据结构

### shelves.json —— 家里的书架子

```json
{
  "levelNote": "层号从最下层往上数，最下层是第 1 层",
  "shelves": [
    { "id": "main", "name": "主卧书架", "emoji": "🛏️", "levels": 4, "note": "" },
    { "id": "entry", "name": "玄关书架", "emoji": "🚪", "levels": 3, "note": "" },
    { "id": "second", "name": "次卧书架", "emoji": "🛌", "levels": 3, "note": "" }
  ]
}
```

**层号约定**：从最下层往上数，最下层是第 1 层。回答位置时统一说成「主卧书架 · 第 2 层」，不要只说「书架上」。网页上第 1 层显示在最下面。
书架与层数由用户口述维护：用户说「玄关书架改成 4 层」就改 `levels`。

### books.json —— 书目总表

```json
{
  "updated": "2026-09-19",
  "books": [
    {
      "id": "B001",
      "title": "小巴掌童话",
      "author": "张秋生",
      "publisher": "长江少年儿童出版社",
      "intro": "一篇篇短短的小童话，像小巴掌一样轻轻拍在孩子心上……",
      "tags": ["童话", "短篇", "语文"],
      "topics": ["睡前故事", "想象力", "好词好句"],
      "suitableFor": "一年级亲子共读 / 自主阅读",
      "cover": "images/covers/cover_20260919193000_a1b2c3.jpg",
      "sources": ["https://book.douban.com/subject/xxxx/"],
      "location": { "shelf": "main", "level": 2 },
      "readStatus": "unread",
      "addedAt": "2026-09-19",
      "source": "拍照录入",
      "infoStatus": "ok"
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | `B001` 起自增，编号只增不删 |
| `tags` | 客观分类（童话 / 科普 / 数学 / 情绪…），供页面筛选与检索 |
| `topics` | 能回答孩子哪些问题（如「为什么下雨」「交朋友」），**推荐书时主要靠它** |
| `location` | `{"shelf": 书架id, "level": 层号}`；`null` = 还没归架 |
| `cover` | 相对本技能根目录的路径；无照片时留空字符串 |
| `sources` | 联网补齐信息时留下的来源链接（简介/出版社的出处） |
| `infoStatus` | `ok` = 信息齐全；`待补充` = 出版社或简介还缺 |
| `readStatus` | `unread` / `reading` / `read` |

## 流程一：拍照录入一本书

触发：用户发送图书照片（封面/封底/内页），或说「记一本书」。

1. **读图提取**：用读图能力识别封面书名、作者、出版社（常在封面下部或书脊）、丛书名；若照片含封底、版权页或内页简介，**优先直接读取简介原文**。
2. **联网补齐**（信息不全时）：用「书名 + 出版社」检索（豆瓣读书、出版社官网、百科），确认完整书名、作者/译者、出版社、出版年、内容简介。把用到的链接写进 `sources`。
   - 检索不到就**问用户**（「这本书的出版社我没认出来，能拍一下封底吗？」），**绝不编造出版社、作者或简介**。
3. **存图**：复制到 `images/covers/`，命名 `cover_YYYYMMDDHHMMSS_随机6位.jpg`；在 `books.json` 里写相对路径 `images/covers/xxx.jpg`。
4. **确定位置**：问「这本书放在哪个书架、第几层？」用户没说就**先不归架**（`location: null`），回执时提醒一句。已经把整箱书交给用户处理时，同一批逐本确认。
5. **写标签**：`tags` 给客观分类，`topics` 写成孩子会问的问题式短语（如「为什么会下雨」「怕黑怎么办」），2-6 个。
6. **追加记录**：在 `books.json` 的 `books` 数组追加，`id` 取现有最大编号 +1，更新 `updated`。封面已有、出版社与简介齐全时 `infoStatus` 写 `ok`。
7. **回执**：书名 + 出版社 + 位置 + 当前藏书总数。

入库后**补一次配音**：调用 `voice-dubbing` 技能（`python .trae/skills/voice-dubbing/tools/gen_tts.py`），让这本书的「书名＋简介」有朗读音频，否则图书馆页点 🔊 在手机上可能没声音。

一次发多本时逐本执行并分别回执，最后给一句汇总（如「这 5 本都放在主卧书架第 3 层了」）。

## 流程二：上架 / 搬家 / 修改信息

触发：「把《X》放到次卧书架第 2 层」「玄关书架改成 4 层」「这本书的简介补一下」。

- **归架/搬家**：找到记录，改 `location`（书架 id 必须存在于 `shelves.json`，层号不超过该书架 `levels`）。层号超范围时提醒用户并确认。
- **书架改造**：改 `shelves.json` 的 `levels` / `name`；若某层已有书而层数被改小，先问用户那些书搬去哪。
- **补全信息**：写入新值，`infoStatus` 改为 `ok`；改完书名或简介后调用 `voice-dubbing` 技能重新生成这本书的朗读音频。
- 改完回执「新位置」与「这本书在书架上第几层」。

## 流程三：按问题推荐书（核心场景）

触发：用户描述一个问题、困惑或想了解的主题（「他最近总跟小朋友抢玩具」「为什么会打雷」「想学写字」）。

1. **抽主题**：从问题里抽出 2-4 个主题词，并做一次口语到书目标签的转换（例：抢玩具 → 分享/友谊/社交；怕黑 → 情绪/勇气；打雷 → 科学/自然）。
2. **匹配**：在 `books.json` 里按 `topics` > `tags` > `title` > `intro` 的顺序匹配，取 1-3 本。
3. **回复必须包含位置**：每本写清「书架名 · 第几层」。`location` 为空时**如实说「还没归架」**，不要编位置；可以顺带请用户确认它现在在哪儿。
4. **说明理由与读法**：一句话讲为什么这本书对口，再给一句可操作的读法（读哪一篇、读后问什么问题、可以玩什么）。
5. **没有对口的书就直说**：不要硬凑。可以说书架上暂时没有，并列出最接近的 1-2 本，或建议补一本什么类型的书（可提议把书名加入 `growth-home/data/booklist.json` 的「书单」）。
6. 书架上没有这本书时不要虚构书名、也不要把没录入的书说成「家里有」。

回复模板：

```
📚 给你推荐家里的这 2 本：

1.《小巴掌童话》· 长江少年儿童出版社
   📍 主卧书架 · 第 2 层
   为什么：里面都是短短的小故事，正好能聊聊「心里的小情绪」。
   怎么读：先读《两颗小石子》，读完问他「如果是你，你会怎么做？」

2.《……》
   📦 还没归架（你告诉我它在哪儿，我就补上位置）
```

网页端「帮我找书」用同一套思路做即时匹配（页面端按标签打分），两者结论应保持一致；网页匹配不到时以本技能的口头推荐为准。

## 流程四：网站展示（成长家园门户集成）

- 门户 `growth-home/web/preview_server.py` 已把 `/lib/*` 映射到本技能根目录；首页标签页「图书馆」（📖）加载 `/lib/web/library.html`。
- 读写方式：页面**读取**走静态 JSON（`/lib/data/books.json`、`shelves.json`、`config.json`）；页面里的「添加图书 / 保存位置 / 删除」**写入**走接口 `POST /api/library`（`op: add|update|delete`），封面照片走 `POST /api/library/upload`（multipart 字段 `image`，存到 `images/covers/` 并返回相对路径）。
- 也可以直接改 JSON：用本技能录入/归架后**无需额外发布**，刷新页面即见。
- 启动：`python <growth-home技能目录>/web/preview_server.py`，浏览器打开 `http://localhost:8090/`，切到「图书馆」标签；手机同 WiFi 访问 `http://<电脑IP>:8090/`。
- 页面零外部依赖，遵循门户工程约定：themes.js 主题实时同步、pinyin-pro 拼音标注、语音朗读（iOS `cancel()` 后留 50ms 再 `speak()`）、反馈按钮只在顶层窗口渲染。
- **语音输入**：页面用全站通用的「语音记录」组件（`vendor/voice.js`）——「帮我找书」提问框下方的 🎤 说完自动识别成文字并立刻找书（场景 `library-ask`），图书信息弹层里的「内容简介」也能口述（场景 `library-intro`）；音频与文字都存档在门户 `growth-home/data/voice/`。手机上非 https 打不开麦克风时，用系统「录音机」录好再点「📁 上传录音」。细节见 `growth-home/SKILL.md` 的「语音记录」一节。
- **语音必须双显示**（门户通用约定，详见 `growth-home/SKILL.md` 的「通用约定」）：一段语音要同时给出「▶️ 能听 + 文字能读」，不许只留音频或只留文字。

## 流程五：盘点与统计

触发：「图书馆里有多少本书」「主卧书架第 2 层有哪些」「哪些书还没归架」。

- 默认在对话里用表格简要回复；**位置一律写成「书架 · 第几层」**。
- 可以顺手给出有价值的提醒：还有几本 `infoStatus` 为「待补充」（请用户拍封面/封底）、哪些层还是空的（新书可以往那儿放）。
- 用户要文件时才生成 HTML 统计页，放 `output/`（目录按需创建）。

## 注意事项

- 全程使用中文，面向家长与孩子，语气亲切、鼓励。
- **不编造**：出版社、作者、简介未确认前宁可问用户；`sources` 只记真实检索到的链接。
- 不擅自删除书目；`id` 只增不减。用户要求删除时先确认书名。
- 位置信息以 `shelves.json` 为准；用户口述的书架与层数与配置不一致时，先核对再改数据。
- 一次入库多本时，逐本确认位置，避免整批书落到错误的层。
