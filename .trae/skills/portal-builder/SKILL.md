# 门户建站（portal-builder）

用户不会写代码，他只会说"我想有个页面看孩子练琴"。这个技能负责把这句话变成**一页真能用的网页**：
复用门户已有的组件与约定，接进菜单和服务器，最后自己点一遍确认没白屏。

## 边界（先看清楚，别越界）

- **它造页面，不造数据层**。隐私数据的落点、读写接口的规则属于项目规则第 8 节，由门户服务器
  （`growth-home/web/preview_server.py`）与各技能自己的 `data/` 承担，本技能只遵守、不重定义。
- **它不改公共页面**。改别人的页面会让下次升级互相打架。要新功能 = 新页面或新技能
  （见 `.trae/rules/project_rules.md` 第 8 节第 3 条）。
- **它不重复造组件**。日历打卡、录音、朗读、主题、拼音、反馈按钮全都有现成的（见契约文件），
  一律复用；自己另写一套会被判定为没做完。

## 什么时候用

用户说："加一个页面 / 加个打卡页 / 做个统计页 / 我想看 XX 的进度 / 把 XX 放到首页菜单 /
改一下首页的样子 / 换个风格 / 新页面接进门户"。

## 工作流程

**第 1 步：先看现状，别凭记忆改。** 跑：

```bash
python tools/portal_wire.py list      # 现有标签页、菜单次序、兄弟技能挂载、重定向
```

同时看一眼 `growth-home/SKILL.md` 的「通用约定」与 `references/page-contract.md`。

**第 2 步：问清需求**（一次问全，别挤牙膏）。至少要问到：

1. 这页给谁看？（孩子自己打卡用 / 家长看进度用）
2. 有没有"记录"？记录什么、多久一次？（有记录就必须走跨设备同步，见契约）
3. 要不要日历打卡？（要 → 复用 `HwSection.mount`，别另写日历）
4. 要不要录音、朗读？（要 → `Voice.attach` + `data/tts/` + `voice-dubbing` 补配音）
5. 页面放哪：门户内（`growth-home/web/`）还是新开一个技能（`tools/new_skill.py`）？
   —— 只服务这个家、逻辑简单 → 门户内新页；有独立数据与流程、将来要分享 → 新技能页。

**第 3 步：定放法**（决定要动哪些接线点）：

| 放法 | 需要动的地方 |
|---|---|
| 门户内新页 | 只加 `CORE_TABS` + `TAB_ORDER`（`portal_wire.py add-page` 就够） |
| 新技能的页面 | 上面两项 **+ 兄弟技能静态挂载**（`add-page --mount <前缀> --skill <技能目录>`） |
| 打卡型标签（读书/家务/运动那种） | 数据侧的 `data/activities.json` 的 `tabs` —— 让用户确认后改数据文件（**这是用户数据，不是代码**） |

**第 4 步：生成页面。** 按 `references/page-contract.md` 的骨架来：零外部依赖、`vendor/` 里五个组件
相对路径引入、大按钮、拼音、点一下才出声、有「☁️ 已同步 / ⚠️ 暂时连不上服务器」这行小字。做法示例见
`references/recipes.md`。

**第 5 步：接线。**

```bash
python tools/portal_wire.py add-page --id <id> --name <名字> --emoji <图标> --src <地址> [--mount <前缀> --skill <技能目录>]
```

**第 6 步：验收（不能跳）。**

```bash
python tools/smoke_test.py          # 起服务逐页检查，页面白屏/接口 404 立刻暴露
python tools/privacy_guard.py --all # 隐私守卫：页面/脚本里不许出现真实姓名、学校、本机路径
python tools/voice-dubbing ...      # 页面里有会被朗读的新文字时补配音
python tools/sync_vendor.py         # 新技能的 vendor/ 有改动时对齐五份
```

不合格就用 `python tools/portal_wire.py undo` 回退，别把半成品留在门户里。

**第 7 步：交回用户**。说清三件事：页面在菜单的哪个位置、这页怎么用（点哪里做什么）、
数据存在哪（哪个 `data/*.json`）。如果用户想撤销，`portal_wire.py remove-page --id <id>`。

## 铁律（违反就算没做完）

1. **记录必须跨设备同步**：记录类数据落服务器 `data/*.json`，页面走 `GET/POST /api/...`，
   按 `ts` 取新合并；`localStorage` 只能当断网缓存。自检：手机、平板、电脑看到同一份数据。
2. **语音双显示**：音频 + 识别文字一起给，用 `vendor/voice.js`，不自己写录音 UI。
3. **整页只留一个打卡日历**，且打卡粒度到"知识点/具体一项"，不要笼统的维度大按钮。
4. **孩子的隐私数据只落 `data/`**：页面、脚本、示例数据里不许出现真名/学校/手机号/本机绝对路径。
5. **儿童友好**：零外部依赖、大按钮、拼音标注、只在点击时出声、庆祝动画可点掉。
6. **接进菜单顺序**：新页默认排在末尾；要固定位置就用 `--after <已有标签id>` 指定。
